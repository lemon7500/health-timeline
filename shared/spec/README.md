# 病程日历跨平台数据协议

`manifest.json` 当前版本为 3。Android、iOS 与 HarmonyOS NEXT 必须先验证整个清单和所有附件，再允许预览、合并或替换。v3 增加 `members`，并要求病情分类、病历、复查计划和药物通过 `memberUuid` 关联家庭成员；至少保留一个未归档成员。

加密容器保持兼容 Android 1.x：

1. ASCII 魔数 `HTBACKUP`。
2. 32 位大端容器版本，当前为 `1`。
3. 32 位大端盐长度、16 字节随机盐。
4. 32 位大端 IV 长度、12 字节随机 IV。
5. PBKDF2-HMAC-SHA256，210,000 次，生成 256 位密钥。
6. AES-256-GCM，128 位认证标签；密文内容是 ZIP。

ZIP 只允许 `manifest.json` 和清单声明的 `files/{attachmentUuid}`。单附件上限 100 MiB，清单上限 10 MB，每类记录上限 100,000。导入实现必须防止路径穿越、整数溢出和部分写入。

格式约定：

- UUID 使用 RFC 4122 文本形式。
- 日期使用 `yyyy-MM-dd`。
- 本地服药/提醒时间使用 `HH:mm`。
- 时间戳使用 UTC ISO-8601，例如 `2026-09-03T00:00:00Z`。
- 星期一至星期日为 1–7。
- 未识别的 schema 版本必须拒绝，不能尝试降级读取。

导入规则：

- v3 以 UUID 去重，冲突默认保留本机；备份包含整个家庭的全部成员与附件。
- v2 是单人格式，合并时归入用户当前选择的成员；整体替换时创建“本人”档案。
- v1 没有稳定 UUID，可为所有条目生成新 UUID 后作为新资料导入当前成员，或经过安全备份后整体替换；不自动去重合并。
- 引用关系、附件大小和 SHA-256 全部验证成功后才可提交；提交失败必须保留原数据库。

机器可读定义见 `backup-v3.schema.json`；`backup-v2.schema.json` 保留用于兼容测试。
