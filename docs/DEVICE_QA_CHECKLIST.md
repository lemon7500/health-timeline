# Android 1.3.1 华为、荣耀、Redmi 真机验收清单

记录测试机型、系统版本、Android API、测试日期和测试人，并在至少一台华为、一台荣耀及一台 Redmi 手机上完成。只使用专门构造的测试资料，不使用客户唯一的真实数据。

1.3.1 为候选版本（`versionCode=14`）；以下空白项均为待验收，不表示已经通过。Room 保持 v8，备份保持 v5，从 1.3.0 升级无需新增数据库迁移。

## 今日总览

- [ ] 冷启动进入“今日”，底部五个入口可用；从后台返回保留原页面，未通过应用锁时不显示医疗内容。
- [ ] 顶部日期、成员姓名和关系正确；切换成员清除旧内容并关闭未提交确认框，不短暂串出其他成员资料。
- [ ] “记录今天病情”默认今天并固定所属成员；取消表单不产生资料，返回后不重复打开。
- [ ] 今日用药与当天用药日历一致：多时间、历史剂量、实际时间、状态及结束当天均正确；未记录项优先且默认最多 3 项，已记录内容可展开。
- [ ] “已服”确认显示成员、药名、剂量及实际时间，可按 5 分钟调整；跳过不保存实际时间，取消确认不写数据。
- [ ] 已记录事项只能进入当天详情修正；连续点击、通知与首页同时操作只写入一次。
- [ ] 结束疗程当天内容不消失，未记录项标注“疗程已结束”且无继续服药按钮；按需药物无虚构待服计划，可补记。
- [ ] 逾期未处理与今天起连续 7 天复查分组、日期、病情分类、提前天数正确，默认每组最多 3 项；同计划同日期不重复。
- [ ] 到期及逾期可确认完成或跳过，未来只查看；查看首页不推进日期，确认处理后仅推进一次。
- [ ] 关闭通知或通知尚未生成待处理记录时，首页仍显示应处理事项，完成/跳过成功并无重复复查记录。
- [ ] 确认中删除事项、归档成员或改变日期后，旧操作不可继续提交，也不写入其他成员资料。
- [ ] 通知关闭、提醒类别关闭、精确闹钟未授权、从未备份及超过 30 天备份显示提示；点击进入安全检查，不反复弹窗、不扫描全部附件。
- [ ] 跨午夜、跨月、跨年、时区变化及前后台切换后日期和事项刷新；后台不持续刷新页面。
- [ ] 空资料、长药名、多事项、小屏、大字体与屏幕阅读器均能正常查看和确认，不将“未记录”标作漏服。

## 安装、升级与隐私

- [ ] 正式签名 APK 可正常侧载、首次启动和覆盖升级。
- [ ] 系统权限页确认应用没有网络权限。
- [ ] 拒绝通知权限时，应用设置页显示明确警告。
- [ ] 锁屏通知仅显示“病程日历提醒”，不暴露成员姓名、病情或药名；解锁状态只显示成员关系和提醒类型。
- [ ] 开启应用锁后可使用指纹、面容或锁屏密码进入；取消验证不会进入应用。
- [ ] 离开应用超过约 30 秒或锁屏后重新验证；相机和文件选择器返回时不误锁。
- [ ] “安全与提醒检查”能识别通知运行时权限、应用通知总开关、复查/用药提醒类别和精确闹钟的真实状态；从系统设置返回后立即刷新。
- [ ] “发送 10 秒测试提醒”可触发通知；未允许通知时按钮不可用，未允许精确闹钟时明确提示可能延迟。
- [ ] 标准电池优化状态正确显示，并提示华为、荣耀、Redmi 的厂商后台开关无法自动读取。

## 家庭成员隔离

- [ ] 新增“本人”“母亲”等至少两个成员，成员页只显示“姓名”和“关系”；日历、搜索、复查、用药只显示当前成员资料。
- [ ] 新增页面打开后资料固定归属于打开页面时的成员。
- [ ] 归档成员后其资料保留、提醒暂停；恢复后提醒重新建立。
- [ ] 有历史资料的成员只能归档；空成员可确认删除；最后一个有效成员不能归档或删除。

## 病历和附件

- [ ] 7 月 9 日新增病历后，月历日期下显示标题。
- [ ] 同一天建立 3 条记录时显示两个两行标题和 `+1`，每条使用独立浅色圆角标签。
- [ ] 搜索标题、分类、诊断、治疗、用药和备注均可找到记录，点击结果能定位到对应日期。
- [ ] 病历新增、编辑、删除及病情分类归档行为正确。
- [ ] 快速录入一段含至少 3 个不同日期的自然叙述，能拆成 3 条；分别展开并修改医生、诊断、分类和标题后，准确保存到对应日期。
- [ ] 批量快速录入中任意一条格式错误时不能保存；模拟保存失败后不留下任何半成品记录或空分类。
- [ ] “复制 AI 整理提示词”只复制提示词和空模板，不包含快速录入框中的测试病历；复制成功后显示明确提示。
- [ ] 外部 AI 返回的多日期及同日多事件模板能拆成独立记录；Markdown 代码框、额外说明和缺失日期均有明确提示。
- [ ] AI 或用户填写“术后复查鼻窦炎”等病名在后的标题时，核对及保存结果自动规范为“鼻窦炎术后复查”；已在首位时不重复病名。
- [ ] 从剪贴板粘贴、中文输入法语音输入、50,000 字上限和未识别内容提示均正确；每条快速录入备注以“原文记录：”开头，编号、句子与事件顺序不变。
- [ ] 连续快速点击两次“保存”，只生成一条记录。
- [ ] 同一病历可导入多张照片和多个 PDF，重启后仍可查看。
- [ ] 相机拍照、图片缩放、PDF 翻页正常。
- [ ] 每张图片和每份 PDF 均可单独删除；确认框显示文件名，重复点击不崩溃、不删除其他附件。
- [ ] 模拟附件移动后进程中断：数据库记录仍存在时重启恢复文件，记录已提交删除时清理临时文件。
- [ ] 超过 100 MB、损坏、无空间或不支持的附件不会留下半成品。

## 复查提醒

- [ ] 7 月 9 日设置每 3 个月，下一次为 10 月 9 日。
- [ ] 1 月 31 日每月提醒依次为 2 月末、3 月 31 日。
- [ ] 每周四提醒可跨月和跨年。
- [ ] 提前 0/1/3/7 天和提醒时间正确。
- [ ] 新建复查默认提前 3 天；升级前已有计划保持原提前天数。
- [ ] 提醒触发后显示待处理项，可标记完成或跳过。
- [ ] 同一个提醒被系统重复投递时只生成一个待处理项，且只有完成/跳过后才推进下一次日期。
- [ ] 重启、修改时区和修改系统时间后仍有提醒。
- [ ] 关闭精确闹钟权限时显示降级警告，并仍收到可能延迟的提醒。

## 用药

- [ ] 每日 08:00、20:00 各产生一剂且分别提醒。
- [ ] 通过小时/分钟滚轮选择 08:05、12:35 等非整点时间；分钟只能按 5 分钟步进，修改和删除时间正常。
- [ ] 应用内“已服/跳过”只写入一次；通知“核对并记录”只打开对应成员/日期，不自动打卡，启用应用锁时必须先验证。
- [ ] 修改剂量后，历史记录仍保留原剂量快照。
- [ ] 用药月历跨月、跨年显示；点击某天按计划/实际时间查看药名、剂量及已服、跳过、未记录状态。
- [ ] 今天和过去日期可补记，未来只读；已服/跳过可二次确认后互改，已服实际时间可修改。
- [ ] 编辑时间、剂量或定时/按需模式后，新计划默认次日生效，过去日期仍显示旧时间和旧剂量。
- [ ] 结束疗程后不再产生提醒，历史日志保留。
- [ ] 尚未到开始日期及已经超过结束日期的药物不产生提醒。
- [ ] 新计划明天生效时，今天尚未到时的旧时间继续提醒；跨日后旧时间停止、新时间接续。
- [ ] 结束/删除疗程后旧通知取消；旧 APK 残留的“已服”按钮不能写入日志。
- [ ] 疗程开始日期不能越过已保存的历史计划或日志；未来疗程不能提前结束，失败后资料完全不变。

## 备份与故障恢复

- [ ] 从带完整虚构资料的 1.3.0 覆盖安装 1.3.1：包名、签名一致，病历、附件 SHA-256、复查、药物、打卡、成员、回收站、提醒和备份逐项保留。
- [ ] 从 1.2.7 直接覆盖安装 1.3.0，病历、附件、复查、药物、打卡、成员、提醒和安全中心状态均保留。
- [ ] 删除一条带多份附件的病历后，病历和本次随病历删除的附件均进入回收站；恢复后内容、UUID、文件和 SHA-256 不变。
- [ ] 先单独删除附件，再删除所属病历；恢复病历时不得误恢复先前单独删除的附件，之后可单独恢复该附件。
- [ ] 删除复查计划后提醒停止；从回收站恢复后有效提醒重新建立，不产生重复提醒。
- [ ] 删除药物后用药月历不再显示该疗程，历史打卡仍在回收站数据中；恢复后原计划、日志和剂量快照完整出现。
- [ ] 回收站只显示当前家庭成员资料，切换成员不会串数据。
- [ ] 永久删除必须二次确认；取消确认不改变数据，确认后项目及所属文件不可恢复。
- [ ] 构造超过 30 天和未满 30 天的回收站资料，重启后只自动清理到期资料；清理文件失败时数据库记录仍保留供重试。
- [ ] v5 加密备份包含回收站内容；恢复后剩余期限、项目关系和附件校验值正确。
- [ ] v1、v2、v3、v4 仍可导入；错误密码、损坏 v5、缺失附件或非法删除时间不得改变本机资料。
- [ ] v4 备份包含全部成员、病历顺序、历史用药计划、提醒、日志和附件，恢复后顺序及成员关系正确。
- [ ] v3 备份导入后补齐病历顺序和历史计划区间；重复导入不产生重复数据。
- [ ] v2 单人备份合并到导入前选中的成员；重复导入不产生重复数据。
- [ ] v1 可作为新资料导入并生成新 UUID；重复导入会明确提示可能重复；整体替换前必须成功导出当前数据安全备份。
- [ ] 冲突默认保留本机，逐条选择导入版本后结果正确。
- [ ] 错误密码、文件损坏、缺失附件、不支持版本和空间不足均不改变当前数据。
- [ ] 恢复过程中强制结束应用并重新启动：原数据或已完整提交的新数据可用，不出现数据库与附件错配。
- [ ] 同长度篡改或删除本机附件后，合并完好的备份能修复文件并通过 SHA-256，重复合并不重复记录。
- [ ] 模拟附件安装后数据库写入失败：原数据库/原文件保持，新附件目录被清理；提交后取消不能删除已经引用的文件。
- [ ] 大写 UUID 的旧清单/ZIP 可以安全导入；大小写冲突的重复 ZIP 路径必须拒绝。

## 安全审查新增验证

- [ ] 新增/编辑病历、批量核对、用药、复查表单在旋转和应用锁重新验证后保留内存草稿；取消、保存成功、成员切换清除草稿。
- [ ] 应用锁锁定时无障碍树不含医疗正文；安全窗口隐藏最近任务缩略图，阻止截屏/录屏。
- [ ] 开启应用锁，在文件选择器打开期间旋转/锁屏，再取消或返回；下一次离开应用超过 30 秒仍必须验证，迟到回调不得清除后台计时。
- [ ] 编辑药物时延迟返回时间表，打开的第二个时间在列表缩短后安全关闭，不崩溃、不误改其他时间。
- [ ] 从历史日期通知定位后旋转/锁定仍保留日期；切换成员不带出其他成员草稿或医疗资料。
- [ ] 超大页面 PDF 不产生越界位图；损坏 PDF 有明确错误且应用仍可继续使用。
- [ ] 病历顺序极值不能导致负数、部分批量保存或历史被改写。
- [ ] 构造含分类、病历、多附件、复查、药物和打卡的 1.1.0/1.2.5 数据，覆盖安装 1.2.6 后数量、内容、UUID、附件 SHA-256、顺序和提醒全部保留。
- [ ] 在 1.2.5 中建立当天有计划和打卡的疗程，升级后点击“结束疗程”；“已结束用药”显示准确结束日期和时间，当天及此前日历记录仍可查看，结束次日起不再生成计划或提醒。
- [ ] 在“已结束用药”点击“恢复疗程”，确认原计划结束日期恢复、历史记录不变、后续日历计划和提醒重新出现；连续点击不得产生重复时间表。
- [ ] 覆盖升级过程中强制中断后，重新启动仍可读取旧数据或完整迁移后的新数据，不出现半迁移。
- [ ] 卸载并重新安装后，可通过备份恢复全部内容。
- [ ] 仅在成功写出加密备份后更新“最近成功备份”时间；取消选择位置或导出失败不得更新时间，超过 30 天显示提醒。
- [ ] 完整性检查能验证数据库、外键、附件存在性、大小和 SHA-256；检查过程不修改任何数据，损坏测试附件时能显示异常数量。
- [ ] 导出的本地诊断报告包含版本、机型、权限和异常数量，但不包含姓名、病历正文、病名、药名、附件名称、路径或 UUID。
- [ ] Room 7→8 迁移中断或校验失败时不清库；重新启动后只能看到完整旧状态或完整新状态，不能出现半迁移。
