# Android 1.2.0 华为、荣耀、Redmi 真机验收清单

记录测试机型、系统版本、Android API、测试日期和测试人，并在至少一台华为、一台荣耀及一台 Redmi 手机上完成。只使用专门构造的测试资料，不使用客户唯一的真实数据。

## 安装、升级与隐私

- [ ] 正式签名 APK 可正常侧载、首次启动和覆盖升级。
- [ ] 系统权限页确认应用没有网络权限。
- [ ] 拒绝通知权限时，应用设置页显示明确警告。
- [ ] 锁屏通知仅显示“病程日历提醒”，不暴露成员姓名、病情或药名；解锁状态只显示成员称呼和提醒类型。
- [ ] 开启应用锁后可使用指纹、面容或锁屏密码进入；取消验证不会进入应用。
- [ ] 离开应用超过约 30 秒或锁屏后重新验证；相机和文件选择器返回时不误锁。

## 家庭成员隔离

- [ ] 新增“本人”“妈妈”等至少两个成员，日历、搜索、复查、用药只显示当前成员资料。
- [ ] 新增页面打开后资料固定归属于打开页面时的成员。
- [ ] 归档成员后其资料保留、提醒暂停；恢复后提醒重新建立。
- [ ] 有历史资料的成员只能归档；空成员可确认删除；最后一个有效成员不能归档或删除。

## 病历和附件

- [ ] 7 月 9 日新增病历后，月历日期下显示标题。
- [ ] 同一天建立 3 条记录时显示两个两行标题和 `+1`，每条使用独立浅色圆角标签。
- [ ] 搜索标题、分类、诊断、治疗、用药和备注均可找到记录，点击结果能定位到对应日期。
- [ ] 病历新增、编辑、删除及病情分类归档行为正确。
- [ ] 连续快速点击两次“保存”，只生成一条记录。
- [ ] 同一病历可导入多张照片和多个 PDF，重启后仍可查看。
- [ ] 相机拍照、图片缩放、PDF 翻页正常。
- [ ] 超过 100 MB、损坏、无空间或不支持的附件不会留下半成品。

## 复查提醒

- [ ] 7 月 9 日设置每 3 个月，下一次为 10 月 9 日。
- [ ] 1 月 31 日每月提醒依次为 2 月末、3 月 31 日。
- [ ] 每周四提醒可跨月和跨年。
- [ ] 提前 0/1/3/7 天和提醒时间正确。
- [ ] 提醒触发后显示待处理项，可标记完成或跳过。
- [ ] 同一个提醒被系统重复投递时只生成一个待处理项，且只有完成/跳过后才推进下一次日期。
- [ ] 重启、修改时区和修改系统时间后仍有提醒。
- [ ] 关闭精确闹钟权限时显示降级警告，并仍收到可能延迟的提醒。

## 用药

- [ ] 每日 08:00、20:00 各产生一剂且分别提醒。
- [ ] 应用内“已服/跳过”和通知“已服”只写入一次。
- [ ] 修改剂量后，历史记录仍保留原剂量快照。
- [ ] 结束疗程后不再产生提醒，历史日志保留。
- [ ] 尚未到开始日期及已经超过结束日期的药物不产生提醒。

## 备份与故障恢复

- [ ] v3 备份包含全部成员、病历、提醒、用药和附件，恢复后成员关系正确。
- [ ] v2 单人备份合并到导入前选中的成员；重复导入不产生重复数据。
- [ ] v1 可作为新资料导入并生成新 UUID；重复导入会明确提示可能重复；整体替换前必须成功导出当前数据安全备份。
- [ ] 冲突默认保留本机，逐条选择导入版本后结果正确。
- [ ] 错误密码、文件损坏、缺失附件、不支持版本和空间不足均不改变当前数据。
- [ ] 恢复过程中强制结束应用并重新启动：原数据或已完整提交的新数据可用，不出现数据库与附件错配。
- [ ] 构造含分类、病历、多附件、复查、药物和打卡的 1.1.0 数据，覆盖安装 1.2.0 后数量、内容、UUID、附件和提醒全部保留，并统一归入“本人”。
- [ ] 覆盖升级过程中强制中断后，重新启动仍可读取旧数据或完整迁移后的新数据，不出现半迁移。
- [ ] 卸载并重新安装后，可通过备份恢复全部内容。

## 电池与后台

- [ ] 自动启动、后台活动和关联启动均按机型要求开启。
- [ ] 熄屏 2 小时及隔夜后，复查和用药通知仍能出现。
- [ ] 低电量模式下记录实际延迟；若系统强制延迟，在安装说明中注明该机型设置路径。
