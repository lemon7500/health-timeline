# 安全审查第一批修复与验证记录

日期：2026-10-09。基线提交：`a48fbaf`，分支：`feature/android-1.2-family-profiles`。

本报告记录审查后的实际代码修复，不是“软件绝对不会崩溃或丢失”的保证。本次未推送、未创建 GitHub Release、未替换原 `dist/HealthTimeline-1.3.1.apk`。正式发布需单独递增版本并完成下述验收。

## Android 已实现

| 风险 | 修复及保护边界 |
| --- | --- |
| 合并备份只凭本机文件存在和数据库中的校验值就复用文件，坏文件可能无法修复 | 复用前读取实际大小与 SHA-256；同一 UUID/选定内容有已验证的备份副本时重新安装，再次校验。无法获得选定内容的完好文件则停止，不覆盖现有数据库。 |
| 恢复提交后取消可能清除新数据库正在引用的附件 | 提交阶段禁止协程取消，记录提交状态；只清理未提交目录。实际进程中断/断电仍待故障注入。 |
| 修改药物的新计划明天生效，却马上停用今天的旧提醒 | 旧计划保持启用至有效区间结束；由时间区间决定提醒截止，新计划从生效日接续。 |
| 修改开始日期或结束未来疗程破坏历史计划、备份引用 | 事务内校验历史计划/打卡最早日期、生效日期、结束区间及有效成员；无效操作整体拒绝。旧版遗留异常停用区间不猜测重建或误启用。 |
| 通知直接打卡可绕过应用锁，残留通知可能误记已结束疗程 | 改为显式 Activity 核对导航，启用保护时先验证，用户确认后才打卡；旧广播按钮不再写数据库。结束/删除后取消该药物现存提醒通知。 |
| 提醒定位异常可能通过 Compose 协程导致崩溃 | 捕获仓库/成员选择写入异常，不产生日志；取消异常仍正确传递。 |
| 旋转、应用锁移除页面使未保存表单丢失 | 草稿仅存 ViewModel 进程内存，重建可以继续；取消、保存成功、成员切换清除。不承诺系统杀死进程后恢复未保存内容。 |
| 历史日期定位在旋转或解锁后跳回今天 | 选中日期与尚未消费的导航保留在内存；只在匹配成员的页面消费目标。 |
| 系统截图、录屏、最近任务缩略图泄露医疗界面 | 启用 `FLAG_SECURE`。这是操作行为变化：Android 界面禁止截屏/录屏；厂商实际表现仍待设备验证。 |
| 巨大 PDF 页面产生超大位图 | 限制宽 1600、高 2000、总像素 320 万，拒绝无效尺寸。不等同于证明系统 PDF 引擎不存在漏洞。 |
| UUID 大小写差异导致跨平台重复/关联失败 | 标识、引用及备份附件路径规范化，保留现有数字 ID；读取旧大写 ZIP 路径，拒绝大小写含混的重复路径。不改写医疗正文。 |
| 同日独立病历合并产生相同顺序或重复导入伪冲突 | 保留本机相对顺序，新增 UUID 按导入顺序追加；派生顺序不同不作为医疗内容冲突。 |
| 病历顺序整数溢出 | 保存及批量保存事务内安全拒绝溢出；共享协议限制极值，不产生负编号或半批记录。 |

保持包名、Room v8、备份 v5、权限清单及发布密钥配置不变，没有数据库迁移、清库或自动重装。备份仍为 PBKDF2 210,000 次与 AES-256-GCM。

整体替换仍必须先成功导出当前数据安全备份；本机已有坏附件时不能绕过这个保护。可先用完好备份合并修复对应附件，再执行安全整体替换。
