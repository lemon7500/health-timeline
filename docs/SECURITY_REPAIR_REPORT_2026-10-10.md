# 安全续修与 CI 验证范围

日期：2026-10-10；修复基线：`a48fbaf`；分支：`feature/android-1.2-family-profiles`。

本轮承接 [第一批安全修复](SECURITY_REPAIR_REPORT_2026-10-09.md)，只提交源码和测试，不创建 Release、不打发布标签、不替换客户安装包。CI 通过不等于真机验收通过。

## Android 追加修复

- 外部文件选择器的临时应用锁豁免在返回前台时结束，不依赖可能因旋转/锁定而遗失的页面回调；迟到回调不能清除其他后台操作的计时。
- 用药编辑器收到迟到、较短的时间列表时关闭旧时间选择器，并在显示和确认前检查索引，避免越界或误改项目。
- 前批附件恢复、UUID 去重、历史用药、通知核对、草稿内存保护和 PDF 位图上限一并接受本次完整 CI 验证。

本机重新实际执行 94 项 Android 和 21 项共享核心 JVM 测试，合计 **115 项通过，0 失败、0 错误、0 跳过**。新增四项应用锁仪器回归，仪器测试共 **91 项**；本机只有测试包编译条件，实际执行由 GitHub Android 模拟器完成，不能把编译算作通过。

保持 Android 版本配置、Room v8、备份 v5、原包名和签名配置不变。不新增权限、不清库、不改历史 schema、不卸载重装。

## iOS 与 HarmonyOS NEXT 续修范围

这两端仍是开发预览，不因源码安全修复而转为可交付客户的正式版本。

- iOS：病历/复查/疗程日期和本地用药时钟改为稳定字符串，审计时间仍为绝对时间；旧数据缺少原时区，不能猜回原日期，转换前保留加密原始数据并提示核对。
- iOS：复查处理核对事项 UUID 和页面所显示的应复查日期，防重复推进；重建通知排除已处理事项和已打卡用药。
- iOS：普通保存与启动采用一致的候选数据校验，超长或无效资料在保存前拒绝，不让一次录入导致重启后整份资料不可加载；过期补发通知保留秒数，不截断到已过去的整分钟。
- iOS：编辑页面未明确修改的日期保留原始字符串，跨时区、夏令时和跳过日期不因仅修改标题/说明而覆盖；用药提交重新核对成员、疗程、计划及实际时间。
- 鸿蒙：历史日查询不再将“通知暂停”当作“历史不存在”；使用历史计划和日志中的剂量，结束当天可查询，恢复仅启用明确由结束操作暂停的计划。
- 鸿蒙：提交前核对当前成员、项目和版本；用药状态变更串行事务保存，失败不覆盖其他已提交修改，加载失败保持不可写。

仍安全拒绝 Android v5 备份，直到两端的回收站和完整 v5 模型实现，不能静默丢弃相关资料。

## GitHub 完整测试门禁

现有 `build-and-test` 工作流运行以下四组，不取消或跳过失败用例：

1. Android/共享核心 JVM 测试、Release Lint、Debug/测试 APK/Release 构建。
2. Android API 35 模拟器：Room 连续迁移、仓库完整性、备份故障路径、成员隔离、通知、应用锁和 Compose 界面仪器测试。
3. macOS：共享 iOS Framework、iOS 模拟器编译和 XCTest。
4. 鸿蒙与备份协议：黄金样本、兼容性及纯用药/事务逻辑测试；这不是 DevEco 编译或鸿蒙 SDK 真机验证。

本地鸿蒙协议和 **14 组实际 `.ets` 业务回归**通过；这些回归使用模拟的 SDK/RDB 接口，未伪装为完整平台测试。

本轮增加成功或失败均可保存的 JVM/Lint 报告，以及 iOS 测试日志和结果包，便于核对实际执行数量；工作流的仓库令牌限定为读取源码，不授予发布或修改仓库权限。以本轮提交的 Actions 结果为准，历史绿色 CI 不能替代本批验证；最终运行链接及通过/失败结果随本轮交付回复提供。
