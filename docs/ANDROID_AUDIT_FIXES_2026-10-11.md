## 修复内容

| 编号 | 原因 | 修复与回归范围 |
| --- | --- | --- |
| A-01 | 极早期迁移按计划时间去重，可能删除内容不同的服药记录 | 仅合并全部字段相同的重复项；其他冲突保留在“旧版历史副本”归档疗程中，保留日志 ID、时间、剂量和状态。副本不生成提醒或待服计划，不虚构停药日期，不允许恢复、修改疗程或追加新日志；已有打卡仍可按正常确认流程修正。测试连续迁移、插入失败回滚和备份往返。 |
| A-02 | 全局替换分号、扫描备注内日期会破坏原文并拆错记录 | 只规范换行符，最后一个“其他备注”后的原文完整保留；多条模板使用独立 `---` 分隔。无法确认边界时保留内容并报错。解析、补充原文和保存路径均不得裁掉原文空白。 |
| A-03 | 复查删除前先取消闹钟，数据库删除失败后提醒失效 | 先提交删除，再取消及重建提醒；数据库失败不改变已有闹钟；系统刷新失败明确说明资料已提交而提醒需要检查。 |
| A-04 | 实际服药时间四舍五入，使 23:59 变成当天 00:00 | 实际时间默认向下取到同一天的 5 分钟档位，可手动调整；计划提醒时间的选择规则不变。 |
| A-05 | 应用锁设置写入失败直接抛出异常 | 保留当前锁状态，返回失败并显示可操作的错误；首次保护提示也不会因保存失败崩溃。 |
| A-06 | 文件选择器返回时页面状态丢失，密码或安全恢复来源失效 | 由根页面注册导出回调，进程内 ViewModel 保留请求，不把密码写入 SavedState。状态丢失或成员切换明确中止，不执行恢复；提示在旋转或锁定后仍可再次展示。 |
| A-07 | 拍照临时文件未在取消、失败或导入完成后清理 | 导入 Job 完成后清理自有临时照片，取消/失败同样清理；校验 authority、文件名和路径，绝不删除已保存附件。启动仅清理超过 24 小时的中断拍照缓存，避免误删系统相机尚未返回的照片。 |
| A-08 | 解密暂存缺少流式资源预算，系统 GCM 可能缓存整个备份 | 固定使用 Bouncy Castle `bcprov-jdk18on:1.83` 的轻量 AES-GCM 实现，分块处理；保留 HTBACKUP 容器、PBKDF2-HMAC-SHA256 210,000 次和 AES-256-GCM。暂存认证成功前不得解析或安装；加入暂存及最终保存位置的动态磁盘预算、取消、清单大小及中断临时文件清理。 |

## 后续资料隔离修复（仍不发布）

上一轮提交 `509dab6` 的 GitHub Actions #24 四项任务均通过。Android 仪器实际执行 131 项、Android JVM 156 项、共享核心 21 项、iOS 模拟器 36 项；鸿蒙仍仅为模拟业务及协议检查，不是真机结论。

继续核查发现：报告批量导入只携带病历数字 ID，每份附件分别取得写锁；若两份之间整体恢复数据库并复用该 ID，下一份可能关联另一永久身份的病历或成员。

本补丁将病历 UUID 和打开详情时的成员 UUID 固定为导入目标。开始导入及每份复制前，都在数据库写锁内重新核对病历、成员永久身份和未删除/未归档状态；核验与文件复制、插入共享同一把锁。身份变化或任一导入失败时明确停止剩余文件，保留已经成功导入的报告并显示数量；取消不作为普通失败吞掉。不改变数据库、版本、包名、签名或备份格式。

新增 11 项 `AttachmentImportIdentityTest` 仪器回归，使用独立虚构图片及临时目录，覆盖正常导入、病历/成员 ID 复用、捕获前身份变化、所属成员变化、归档、回收站、批次中途替换和已取消 Job 进入导入。该取消测试不等于已覆盖复制中或插入提交后的取消。另用旧数字 ID 导入体重现错误关联，再证明固定永久身份的接口拒绝同一替换场景。执行结果以该补丁对应 CI 为准。

提交前本地完整任务组合构建成功，Android JVM 156 项、共享核心 21 项报告均为零失败；release lint 为 0 错误、58 警告、1 提示。最终仪器 APK 重新编译通过，仪器实际执行及 iOS 模拟器结果待本次 CI。独立只读补丁审查未发现新增阻断问题，但明确保留以下风险。

下列问题仍未修复，不作为本补丁的完成项：

- 拍照/附件选择以及备份导入选择器，在 Activity 重建或应用锁移除页面后，仍可能静默丢失返回结果。需要根页面持续注册回调、保留进程内请求，并补端到端测试。
- `ZipFile` 在检查条目数量前加载中央目录；600,000 个空条目的虚构 ZIP64 在 JDK 32 MiB 堆下先发生内存不足，Android 原生行为未实测。仅换成流式 ZIP 读取会放过损坏中央目录，必须同时解决有界结构验证及 ZIP64/旧备份兼容。
- 整体导入/恢复取消后，提醒重建仍运行在已经取消的协程中，可能留下提醒空档；需针对真实取消和系统闹钟补回归。
- 普通附件复制及数据库插入提交后的精确取消窗口尚未实测；原有文件删除补偿路径需继续复现并核查，不能用本次操作开始前的取消测试替代。
