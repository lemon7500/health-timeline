# 病程日历 Android 1.3.0 第三阶段自查报告

## 结论

1.3.0 的源码实现、JVM 回归测试、Android 仪器测试包编译、Release Lint、R8 正式构建和签名核验均已完成。第二阶段 1.2.7 可继续独立真机测试；第三阶段 1.3.0 在 GitHub 模拟器测试和三品牌覆盖升级验收通过前仍属于候选包。

## 数据保护检查

- `applicationId` 保持 `com.healthtimeline.app`，`versionCode=13`、`versionName=1.3.0`；正式 APK 使用与旧版相同的发布证书。
- Room 由 v7 升级至 v8。正式 7→8 迁移只增加病历、附件、复查和药物的删除时间，以及附件更新时间与必要索引。
- 迁移保留数字主键、UUID、成员关联、附件路径及 SHA-256、复查规则、药物和打卡，并执行逐表数量及 `PRAGMA foreign_key_check` 校验；失败时由 SQLite 整体回滚，不清库。
- 病历、单个附件、复查计划和药物删除后先写入删除时间，30 天内可恢复；活动页面、搜索和提醒查询均排除已删除资料。
- 删除病历时活动附件使用同一删除时间；恢复时只恢复本次随病历删除的附件，不会误恢复此前单独删除的报告。
- 回收站中的复查和药物不能生成提醒或打卡，恢复后重新建立有效提醒。
- 永久删除病历或附件时先将文件移动到内部临时区，数据库提交后再清理；失败时恢复文件。到期清理失败的项目保留供下次重试。
- 病历日期内顺序使用 `dayOrder` 保存；批量记录、日历查询和 v4 备份恢复均按稳定顺序处理。
- 用药时间表采用生效区间版本；编辑时间、剂量或模式时关闭旧区间并创建新区间，历史日历使用计划或日志中的剂量快照。
- 结束疗程在单个事务内保存最后用药日期、精确结束时间和原计划结束日期，并暂停未来计划；日历投影明确包含结束当天，“已结束用药”独立归档展示。
- “恢复疗程”在单个事务内还原原计划结束日期，只重新启用因本次结束操作而暂停的时间表；既往打卡、历史剂量快照、UUID 和创建时间均不改写。由 1.2.5 升级的已结束疗程会把当时被截短的时间表安全转换为可恢复状态。
- 单个附件删除先校验私有附件目录，再移动至内部临时目录，数据库事务成功后才清理；若进程在事务前中断，启动时会依据仍存在的数据库 UUID 恢复文件。过期界面对象及重复删除不能删除其他附件。
- 附件导入继续使用临时文件、`fsync`、格式验证、100 MB 限制及 SHA-256，成功后才登记数据库。
- `.htbackup` v5 保持 `HTBACKUP`、PBKDF2-HMAC-SHA256 210,000 次和 AES-256-GCM；完整保存回收站状态，并兼容导入 v1/v2/v3/v4。
- 备份导入先验证密码、版本、字段、枚举、日期、成员引用、路径、空间、附件大小及 SHA-256；数据库切换使用单个事务，失败不改变现有数据。
- 应用不申请 `INTERNET` 权限；锁屏通知继续隐藏成员、病情和药名。
- 安全检查中心读取通知总开关、复查/用药类别、精确闹钟和 Android 标准电池优化状态；厂商自启动开关无法通过标准 Android API 读取，界面明确要求人工确认。
- 测试提醒使用独立的一次性闹钟和固定隐私文案，不生成复查事项或用药打卡，也不写入病历数据库。
- 最近备份时间只在加密文件成功写入并同步后更新；取消或失败不更新时间。从未记录或超过 30 天会显示提示。
- 手动完整性检查执行 `PRAGMA quick_check`、`PRAGMA foreign_key_check`，并逐份流式验证附件存在性、大小和 SHA-256；检查过程只读。
- 本地诊断报告仅包含版本、设备型号、权限状态、存储空间和异常数量，不包含姓名、病历正文、病名、药名、附件名称、路径或 UUID。

## 尚不能由当前环境证明

- GitHub CI 的模拟器必须实际运行全部 32 个仪器测试，特别是 Room 7→8、事务删除、损坏附件恢复拒绝和过期清理。
- 华为、荣耀、Redmi 仍需验证 1.2.7 覆盖安装 1.3.0、组合恢复、提醒取消/重建及 v5 备份恢复。
- 任何软件都无法对硬件损坏、文件系统故障、用户卸载或清除数据承诺绝对零丢失；正式升级前应导出加密备份，并把备份和密码分开保存。
