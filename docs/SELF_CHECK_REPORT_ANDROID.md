# 病程日历 Android 1.2.0 发布候选自查报告

## 结论

已完成家庭成员、数据库 3→4 迁移、备份 v3、应用锁、提醒隐私及主要失败路径的源码审查和 JVM 构建验证。当前仍是发布候选：Android 设备测试只完成编译，华为、荣耀、Redmi 真机覆盖升级尚未执行，因此不得标记为稳定版。

## 已加强的数据保护

- 1.1.0 → 1.2.0 使用 Room 3→4 正式事务迁移，创建默认成员“本人”，并为全部旧分类、病历、复查和药物写入非空成员外键。
- 迁移保留旧数字主键、UUID、附件路径、校验值、复查记录、服药计划和历史打卡；迁移后校验各表数量及全部外键。
- `applicationId` 保持 `com.healthtimeline.app`，`versionCode=5`、`versionName=1.2.0`；发布 APK 必须继续使用 1.1.0 的原签名。
- 禁止破坏性迁移、自动清库和卸载重装式升级；迁移失败由 SQLite 事务回滚。
- 每个可跨平台实体的 UUID 在编辑时不可更改；成员删除受外键和引用检查双重保护。
- v3 备份要求至少一个未归档成员，跨成员分类引用会被拒绝。
- SQLCipher 数据库使用 WAL、`synchronous=FULL` 和启动 `quick_check`。
- 数据写入、附件导入、备份和恢复共享互斥锁，避免并发交叉修改。
- 附件使用临时文件、`fsync`、格式验证、100 MB 限制和 SHA-256 后才登记入库。
- 备份恢复先验证密码、版本、字段、枚举、日期、成员引用、路径、空间、大小及 SHA-256。
- 恢复附件先安装到独立目录，最后以单个数据库事务切换引用；失败或中断不会让当前数据库引用半成品。
- 整体替换前强制导出用户可保管的安全备份，并在应用私有目录保留最近三份自动安全备份。
- 重复复查广播不会重复推进日期；用药打卡使用数据库唯一索引防重复。

## 尚不能由当前环境证明的事项

- 当前没有连接 Android 模拟器、华为、荣耀或 Redmi 真机，设备测试只能确认编译成功，尚未实际执行。
